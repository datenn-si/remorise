# API

対象読者：API の契約を確認する開発者。

API は FastAPI で提供されます。
対話的な OpenAPI ドキュメントは `/docs` で利用できます。
関連文書は [設定リファレンス](../../docs/settings.md)、[キャラクター設定フォーマット](../../docs/characters.md)、[記憶処理フロー](../../docs/memory-flow.md) です。

## チャット

### `POST /api/chat`

リクエスト:

| フィールド | 型     | 制約           |
| ---------- | ------ | -------------- |
| `message`  | string | 1〜20,000 文字 |

成功時は `Content-Type: text/event-stream` を使い、フレームは `event: <name>\ndata: <JSON>\n\n` の形式です。

| イベント          | データ                                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `message_start`   | `{"message_id": integer}`                                                                                                                             |
| `token`           | `{"content": string}`。生成されたテキストの断片1つ                                                                                                    |
| `usage`           | `{"prompt_tokens": integer, "completion_tokens": integer, "total_tokens": integer}`。応答生成に関するもの。LLM が使用量を報告しない場合は省略されます |
| `state_analysis`  | 生成前に決まる段階 B の感情分析オブジェクト（`emotion` と `affinity`）。アシスタント履歴のメタデータにも `state_analysis` として保存されます          |
| `character_state` | キャラクター状態オブジェクト。感情、強度、副次的な感情と強度、気分、好感度、タイムスタンプ                                                            |
| `message_end`     | `{"message_id": integer}`                                                                                                                             |
| `error`           | `{"code": "generation_failed"}`                                                                                                                       |

生成される OpenAPI スキーマには、すべてのイベントのデータスキーマが `200.content["text/event-stream"].x-sse-events` の下に列挙されます。

1つのターンは3つの段階を実行します。

| 段階 | 処理     | 内容                                                                                                                                                                                        |
| ---- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A    | 記憶処理 | アナリストペルソナの LLM セッション。バックエンドのツール（記憶検索、近傍／期間の参照、保存、訂正、期間の確定、プロフィールの更新）を備え、呼び出し回数・時間・トークンの予算の下で動きます |
| B    | 感情分析 | 段階 A の文脈を決して継承しない、独立したクリーンな LLM 呼び出しです                                                                                                                        |
| C    | 返答生成 | キャラクターの返答生成で、ツールを持ちません                                                                                                                                                |

ヒット条件、類似度ゲート、期間の調整はバックエンドの固定規則であり、開示ゲートを通過した記憶（ヒット、想起、このターンの新しい記憶）だけが先へ進みます。

段階 B は、直近の抜粋、現在の状態、感情の履歴、常駐記憶と最新の開示記憶、最新メッセージ、現在日時、「何か忘れている」という通知を受け取ります。

現在日時は常に段階 A、B、C に注入されます（記憶は絶対的な期間を持つため、位置づけには「現在」が必要です）。
段階 B の結果は検証され、キャラクター状態に適用されたうえで、`state_analysis` と `character_state` として `token` イベントより前に送られます。

段階 A または B が失敗した場合、ターンは確定済みの内容と以前の状態で続行します（フェイルソフト）。
段階 A のツール通信がクライアントへストリーミングされることはなく、アシスタントのテキストとして描画されることもありません。

HTTP エラー:

| ステータス | エラーコード             | 意味                                                                     |
| ---------- | ------------------------ | ------------------------------------------------------------------------ |
| `409`      | `generation_in_progress` | 別の生成が進行中です                                                     |
| `422`      | （FastAPI の検証エラー） | リクエストボディの形式が不正か、チャットメッセージの制約に違反しています |
| `502`      | `llm_error`              | LLM サーバーが失敗の応答を返しました                                     |
| `503`      | `llm_unavailable`        | LLM サーバーに到達できませんでした                                       |
| `504`      | `llm_timeout`            | LLM リクエストがタイムアウトしました                                     |

HTTP エラーのボディは FastAPI の `{"detail":{"code":"..."}}` 形式を使います。
ただし `422` の検証エラーは FastAPI 標準の `{"detail":[...]}` 形式です。
HTTP エラーが返るのは、応答がまだ始まっていない場合だけです。

SSE ストリームが確立した後の失敗は、ストリーム内の `error` イベント（`generation_failed`）として報告され、その時点で HTTP ステータスは変えられません。

クライアントが切断しても生成はキャンセルされません。

受理されたターンはサーバー上で完了まで実行され、応答は保存されるため、クライアントが戻ったときには履歴の中にあります。

停止手段はありません。受理されたターンを外部から中断するものは何もありません。

それ以外の形で中断されたターン（生成の失敗、クラッシュ、バックエンドの終了）は応答を保存せず、再送のためのぶら下がりターンを残します。

### `POST /api/chat/resend`

ぶら下がりターンの生成を再試行します。

対象は、最後のユーザーメッセージで、まだアシスタントの応答がないものです（ユーザーメッセージが保存された後に前回の生成が失敗した状態）。

リクエストボディはありません。

新しいユーザーメッセージは作られず、不足している生成だけが再試行されます。

ストリームは `POST /api/chat` と同じイベント・同じ形式で、`message_start` は既存のユーザーメッセージの ID を伝えます。受理された再送は、新規送信と同じく、クライアント接続から切り離されて実行されます。

前段が1つのメッセージに対して2回実行されることは決してありません。

段階 A の書き込み、ターンの記憶リンク、前段の記録は、最初の試行でユーザーメッセージ上にまとめてコミットされます（`front_stage` メタデータ）。再送はその記録（同じ開示記憶、聞き返し材料、通知）を再利用し、保存された `state_analysis` / `character_state` を再生します。

段階 B は、一度も適用されなかった場合だけ再試行されます（`emotion_applied` フラグがなく、そのメッセージに対する状態履歴の行もない場合）。記録も状態履歴の行も存在しない場合は、最初の試行で何も確定しなかったということなので、前段は新規メッセージの場合と同様に実行されます。

HTTP エラー（ストリームが確立する前）:

| ステータス | エラーコード             | 意味                                                                               |
| ---------- | ------------------------ | ---------------------------------------------------------------------------------- |
| `409`      | `generation_in_progress` | 別の生成が進行中です                                                               |
| `409`      | `no_dangling_turn`       | 最後のユーザーメッセージには既に応答があるか、ユーザーメッセージ自体が存在しません |
| `502`      | `llm_error`              | LLM サーバーが失敗の応答を返しました                                               |
| `503`      | `llm_unavailable`        | LLM サーバーに到達できませんでした                                                 |
| `504`      | `llm_timeout`            | LLM リクエストがタイムアウトしました                                               |

### `GET /api/chat/inference-status`

共有の推論ロックを今誰が使っているかを、メモリ上の状態から報告します（永続化されるものは何もありません）。

| フィールド           | 型                                       | 意味                                                                                                                                                            |
| -------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `active`             | `"background"` / `"foreground"` / `null` | ロックの保持者。後処理ジョブまたはワーカーのハウスキーピングが保持している間は `"background"`、チャットのターンが保持している間は `"foreground"`                |
| `background_kind`    | string / `null`                          | バックグラウンド使用の種別（後処理ジョブの種別、またはハウスキーピングの `"retention"`）                                                                        |
| `foreground_waiting` | boolean                                  | チャットのターンがバックグラウンド作業の後ろに並んでいる間 true                                                                                                 |
| `foreground_phase`   | `"thinking"` / `"speaking"` / `null`     | フォアグラウンドのターンの表示上の段階。最初の可視トークンが出るまでは `"thinking"`、その後は `"speaking"`。フォアグラウンドのターンが実行中でないときは `null` |

チャット UI はこのエンドポイントをポーリングします。

バックグラウンド作業が推論を使っている間、または送信がそれを待っている間、通常の UI はキャラクターを考え中として表示します（考え中マークと柔らかいラベル）。

自分がストリーミングしていないフォアグラウンドのターンについては、`foreground_phase` に従って考え中と発話中を表示し分けます。

### `GET /api/chat/history`

会話の1ページを `{"messages": [...], "has_more": bool}` として時系列順に返します。
パラメータなしでは、アクティブな会話の最新ページです。

クエリパラメータ:

| パラメータ         | 既定値  | 意味                                                                                                                                                                                             |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `limit`            | `100`   | ページサイズ（最大 500）                                                                                                                                                                         |
| `before_id`        | なし    | このメッセージ ID より古いページを返します。遡るためのカーソルです                                                                                                                               |
| `include_archived` | `false` | true の場合、アーカイブ済みの行も含みます。`archived` はその行がアーカイブされているかどうかです。アーカイブ済みなら `true`、同じページのアクティブな行は `false` です。デバッグビューが使います |

`include_archived` でアーカイブされた行が会話に戻ることは決してありません。

アシスタントメッセージの `metadata` には、デバッグモードで使うターンのパイプライン記録も含まれます。

| キー             | 内容                                                                                                                                                                                                                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `state_analysis` | 段階 B の分析                                                                                                                                                                                                                                                                                                          |
| `memory_search`  | 段階 A の記録。`searches`（各検索の検索語、ユーザーが振り返って指し示していたかどうか、結果 `hit` / `no_hit` / `forgotten_undisclosed`）、`disclosed`（ゲートを通過した記憶と、その配信種別 `hit` / `recall` / `new`）、`recalled_ids`、`restored_ids`、`created_ids`、`notification_terms`、`ask_back_ids` を含みます |

通常の UI はこれらを描画しません。
デバッグのタイムラインでのみ表示されます。

## 設定

ランタイム設定は階層化されています。

基底層の値（LLM のエンドポイント、モデル、API キー、データディレクトリ、データベース URL）は `.env` にだけ存在します。

データベースと LLM クライアントが起動時にそれらをもとに作られるためです。

挙動を調整するものはすべてデータベースで上書きでき、再起動なしに設定 API から変更できます。
解決順序は DB の上書き > `.env` > 既定値です。

すべての設定ペイロードで、フィールドへの明示的な `null` はリセットを意味します（その DB の上書きが削除され、`.env` の値が再び効きます）。

マージ後の結果は `.env` 設定と同じ検証に合格しなければならず、合格しない場合、更新全体が `422` で拒否されます。

各層の項目と既定値は [設定リファレンス](../../docs/settings.md) を参照してください。

### `GET /api/settings` / `PATCH /api/settings`

運用層を読み取るか更新します。
挙動の調整フィールドはすべてここにあり、データライフサイクルと忘却のフィールドも含まれます（デバッグ画面は読み取り専用です）。

グループ:

| グループ             | 含まれる項目                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| 生成                 | 最大トークン、LLM のタイムアウト、サンプリング、文脈サイズ                                          |
| 文脈と要約           | 警告／要約／目標の比率、保護される直近のメッセージ                                                  |
| ジョブ               | 最大試行回数、ポーリング間隔                                                                        |
| 感情と好感度         | 感情の半減期、好感度の範囲と変化量の上限                                                            |
| 記憶処理             | 呼び出し上限とタイムアウト、検索ごとの受け渡し上限とトークン予算、常駐集合の上限、類似度しきい値    |
| 忘却                 | 減衰のオン／オフ、しきい値、出来事／状態の半減期、再活性化の倍率と上限                              |
| データライフサイクル | アーカイブ保持期間、生ログ保持期間                                                                  |
| 立ち絵モーション     | `sprite_motion_enabled`、`sprite_motion_amplitude`、`sprite_motion_speed`、`sprite_motion_overscan` |

振幅と速度はレンダラーの組み込みモーションへの倍率で、オーバースキャンは移動中に立ち絵の端が隠れた状態を保つズーム係数です。

立ち絵デバッグページはこれらをライブで調整します。

レスポンス:

| フィールド           | 内容                                                 |
| -------------------- | ---------------------------------------------------- |
| （各運用フィールド） | そのフィールドの実効値                               |
| `overridden`         | 現在データベースで上書きされているフィールドのリスト |
| `base_values`        | 各運用フィールドの `.env`／既定値                    |
| `readonly`           | 基底層の表示用情報（下記）                           |

`readonly` が伝えるのは LLM のエンドポイント、モデル、API キーが設定されているかどうか、データディレクトリです。

API キーの値自体は返されず、データベース URL は公開されません。

基底層はこの API から変更できません。
運用層の外にあるフィールド（基底層の名前、未知のキー、再設計で削除されたフィールド）は `422` で拒否されます。

## デバッグ

デバッグ API は読み取り専用で、例外はアーカイブ済み履歴の purge だけです。

手動の記憶コントロール（固定／忘却／再活性化）はなく、デバッグ用の設定エンドポイントもなく、手動の履歴クリアもありません。

### `GET /api/debug/history`

メッセージと要約の読み取り専用ビューで、既定でアーカイブ済みの行も含みます（`?include_archived=false` はアクティブな行だけを返します）。
各項目は `archived` と `archived_at` を持ちます。
アーカイブされた内容がアクティブな会話に戻ることは決してありません。

### `DELETE /api/debug/history/purge`

アーカイブ済み履歴を、カットオフまで物理的に削除します。

クエリパラメータ:

| パラメータ           | 必須 | 意味                                                                                                                                  |
| -------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `through_message_id` | 必須 | カット位置。`id <= through_message_id` のアーカイブ済みメッセージと、カバー範囲がその ID 以下で終わるアーカイブ済み要約が削除されます |

削除されるのは、既に無効化された行だけです。

アクティブな行が削除されることは決してなく、選んだ1項目だけを削除する方法もありません。
削除はプレフィックスカットのみです。
`{"purged_messages": n, "purged_summaries": n}` を返します。
アーカイブ済み履歴をオンデマンドで物理削除する経路はこれだけです。

アーカイブされた行は、`ARCHIVE_RETENTION_DAYS` が 0 より大きく設定されている場合にも自動で期限切れになります（既定 0 = 手動 purge のみ）。
自動の形式は、ID の代わりに時刻による同じカットです。
保持期間は運用層の設定で、`.env` を編集せずに `PATCH /api/settings` で変更できます。
応答の生成中は `409 generation_in_progress` を返します。

### `GET /api/debug/memories`

すべての記憶をリストします（忘れられたものも含みます）。
`limit` クエリパラメータで件数を指定できます（既定 100、1〜500）。
`offset` クエリパラメータで開始位置をずらせます（既定 0）。

最後に強化されたものが先頭です（同時刻は ID の降順）。
記憶は物理削除されないため件数に上限はなく、`limit` と `offset` で全件をたどれます。
読み取り専用です。

各項目は期間モデルのフィールドを持ちます。

| フィールド                              | 意味                                                                               |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| `content`                               | 記憶の内容                                                                         |
| `category`                              | `event` / `state`                                                                  |
| `importance`                            | 重要度                                                                             |
| `status`                                | `active` / `forgotten`                                                             |
| `is_active`                             | アクティブかどうか                                                                 |
| `provenance`                            | `explicit` / `inferred`                                                            |
| `keywords`                              | その事実の抽象的な概念語                                                           |
| `specific_terms`                        | 具体的な語（固有名詞など）                                                         |
| `period_start` / `period_end`           | 状態の期間                                                                         |
| `event_at`                              | 出来事の時点                                                                       |
| `provisional`                           | 時刻がまだ確定していないかどうか                                                   |
| `source_type` / `source_date`           | 発生源                                                                             |
| `last_accessed_at`                      | 最後に検索で使われた時刻                                                           |
| `last_recalled_at`                      | 忘れられた記憶が最後に想起された時刻。検索ヒットで設定されることは決してありません |
| `reactivation_count`                    | 想起された回数                                                                     |
| `last_restored_at`                      | 最後に復帰した時刻                                                                 |
| `restoration_count`                     | 忘れられた記憶が言い直しで戻った回数。想起とは別に記録されます                     |
| `last_reinforced_at`                    | 忘却時計の保存されたスタンプ                                                       |
| `content_updated_at` とその発生源のペア | 内容の簿記                                                                         |

### `GET /api/debug/jobs`

最近の後処理ジョブをリストします。新しいものが先頭です（`limit` の既定は 50、最大 200）。読み取り専用です。

| フィールド                            | 意味                                                 |
| ------------------------------------- | ---------------------------------------------------- |
| `kind`                                | ジョブの種別（存在するのは `summary` のみ）          |
| `start_message_id` / `end_message_id` | メッセージ範囲                                       |
| `conversation_epoch`                  | 会話の世代                                           |
| `status`                              | `pending` / `running` / `done` / `failed`            |
| `attempts`                            | 試行回数                                             |
| `error`                               | エラー                                               |
| `result`                              | 常に null です。要約ジョブは結果の内訳を記録しません |

### `GET /api/debug/pipeline`

パイプラインの状態を返します。
読み取り専用です。

| フィールド                    | 意味                                                          |
| ----------------------------- | ------------------------------------------------------------- |
| `epoch`                       | 会話の世代                                                    |
| `summarized_until_message_id` | アクティブな要約がカバーする末尾（まだ要約がない場合は null） |
| `unsummarized_messages`       | アクティブなメッセージのうち、まだカバーされていない数        |
| `pending_jobs`                | 保留中のジョブ数                                              |
| `running_jobs`                | 実行中のジョブ数                                              |

### `GET /api/debug/raw-logs`

最近の生の LLM 呼び出しログをリストします。新しいものが先頭です。

`v0.1.0` 時点では、この API を表示する画面はフロントエンドにありません。
確認するには、データベースファイルを開くか、この API を手動で呼びます。

すべての LLM 呼び出し（段階 A の `memory_agent`、段階 B の `emotion`、メイン生成の `chat`（完了したストリームごとに1行）、要約の `summary`）について、送信されたリクエストと生の応答テキスト（失敗した場合はエラー）、それが属するメッセージ／ジョブが記録されます。

記録はベストエフォートで、会話をブロックすることは決してありません。

クエリパラメータ:

| パラメータ | 既定値 | 意味                           |
| ---------- | ------ | ------------------------------ |
| `kind`     | なし   | 呼び出し種別でフィルタします   |
| `limit`    | `50`   | 件数（200 にクランプされます） |

行は `RAW_LOG_RETENTION_DAYS` の後に期限切れになり、ジョブが所有する行はそのジョブが `done` になるまで保持されます。
フォアグラウンドの行は経過時間だけで期限切れになります。

## 後処理ジョブ

要約が唯一のバックグラウンドジョブです。

`post_jobs` テーブルの行で、`summary`、メッセージ範囲、会話エポック、`pending` / `running` / `done` / `failed` の状態を持ちます。

ワーカーは、要約されていない文脈が文脈サイズの `CONTEXT_SUMMARY_RATIO` に達したとき、保護される直近の末尾（`SUMMARY_PROTECTED_MESSAGES`）を除いて要約ジョブを登録します。

ターンが結果を待つことは決してなく、前回確定した要約と要約されていない末尾から文脈を組み立てます。

ジョブとパイプラインの状態は `GET /api/debug/jobs` と `GET /api/debug/pipeline` で確認できます。
すべての LLM 呼び出しは単一の推論ロックで直列化されるため、バックグラウンドジョブがチャット生成と同時に実行されることは決してありません。

## キャラクター

### `GET /api/character`

選択された、検証済みのキャラクタープロフィールを返します（完全な `character.json` で、`speech_style` を含みます。

チャット UI の情報ビューはこれを読み取り専用で表示します。
編集する API はありません）。

バックエンドは起動時に選ばれたキャラクター ID（起動引数 `--character`、環境変数 `REMORISE_CHARACTER_ID`、既定は `remora`）の `REMORISE_DATA_DIR/characters/<id>/character.json` を読みます。

そのキャラクターが無い場合はエラーをログに出して `remora` にフォールバックし、`remora` のデータフォルダも無ければ同梱の `characters/remora/character.json` を使います。

### `GET /api/character/layers`

選択されたキャラクターのレイヤー設定を返します。
バックエンドは、実行時の画像リクエスト用に `root` を `/api/character/assets` に設定し、`available` を追加します。

背景透過をさせる兼ね合いで、レイヤー画像には PNG のみを使用できます。

`available` が数える参照は、パスが `.png` で終わるものだけです。

| 項目        | 内容                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `root`      | `/api/character/assets`（実行時の画像リクエスト用）                                               |
| `available` | 定義が参照する PNG（`.png` で終わるパス）のいずれかが実際に存在するかどうか。PNG 以外は数えません |

立ち絵のないキャラクター（`available: false`）は、チャットに立ち絵エリアを表示せず、立ち絵デバッグページも開けません。

レイヤーの項目は、プレーンなパス文字列（原点に描かれるフルキャンバス画像）か、立ち絵分割ツールが生成するパーツ形式のオブジェクト `{"path": ..., "x": ..., "y": ...}`（その左上隅がオフセット位置に描かれます）のいずれかです。

完全な形式は [キャラクター設定フォーマット](../../docs/characters.md) を参照してください。

### `GET /api/character/terms`

選択されたキャラクターの利用規約を返します。

キャラクターのフォルダに `terms.md`（Markdown）がある場合に `available: true` とその本文（`markdown`）を返し、無い場合は `available: false` と空の `markdown` を返します。

規約はキャラクターの作者の文書で、本ソフトウェアは表示するだけです。形式は [キャラクター設定フォーマット](../../docs/characters.md) を参照してください。

### `GET /api/character/assets/{asset_path}`

選択されたキャラクターの `layers/` ディレクトリから画像を返します。

存在しないパスや、ディレクトリ外のパスは `404 character_asset_not_found` を返します。

### `GET /api/character/state`

経過時間による感情の減衰を適用した後の、現在の状態を返します。

### `PATCH /api/character/state`

渡された状態フィールドを更新します。

感情の強さは `[0, 1]` の範囲内でなければならず、好感度は `[0, 200]` の範囲内でなければなりません。
`emotion` と `secondary_emotion` は `neutral`、`happy`、`sad`、`angry`、`embarrassed`、`surprised`、`anxious`、`affectionate`、`puzzled` のいずれかです。更新された状態を返します。

`404 character_state_not_found` を返すのは、データベースの初期化が完了していない場合だけです。

## 長期記憶

記憶 API は読み取り専用です。
記憶が書き込まれるのは、前段の記憶処理（段階 A）によってのみです。
API 経由の作成、編集、削除はできません（それらのメソッドは `405` を返します）。

### `GET /api/memories`

記憶をリストします。
最後の強化順です。
各項目は、`GET /api/debug/memories` に挙げた期間モデルのフィールドを持ちます。

クエリパラメータ:

| パラメータ         | 既定値  | 意味                         |
| ------------------ | ------- | ---------------------------- |
| `query`            | なし    | 全文検索（最大 500 文字）    |
| `include_inactive` | `false` | 非アクティブな記憶も含めます |
| `limit`            | `50`    | 件数（1〜100）               |

### `GET /api/memories/{memory_id}`

1つの記憶を返します。非アクティブな記憶も含みます。存在しない場合は `404 memory_not_found` を返します。

記憶のレスポンスは `content_updated_at`、`content_update_source_type`、`content_update_provenance` を持ちます。
その事実自体が最後に変更された時刻と、その変更の出所を、作成時の発生源と同じ形式で示します。

これらが動くのは実質的な内容の変更だけです（一致する保存、訂正による上書き、語の補完）。

ライフサイクルの出来事（忘却、想起、復帰、検索ヒット）では決して動きません。

行に残るもう1つのタイムスタンプが `last_reinforced_at` です。

忘却（減衰）時計の保存されたスタンプで、ライフサイクルの遷移と内容の書き込みの両方で更新されます（通常の検索ヒットは例外で、`last_accessed_at` にだけスタンプし、減衰は3つのうち最新のものから進行します）。
これはライフサイクルのタイムスタンプであり、内容のタイムスタンプではありません。

UI はこれを最後の強化として表示します。

## 運用上の注意

- 記憶検索は、日本語の部分文字列マッチングのために SQLite FTS5 の組み込み trigram トークナイザを使います。  
  対象は、記憶の内容と、保存された両種の検索語（抽象的な概念語 `keywords` と具体的な語 `specific_terms`）、それにカテゴリで、別々の索引列として保持します。  
  そのため、ヒットは各検索語がどちらの側にマッチしたかを知ります（ヒット種別: 具体的／抽象的／両方）。
  ランキングは `importance` でスケールした bm25 です。  
  リテラルな部分文字列マッチングは、trigram には短すぎる語をカバーし（内容と保存された両方の語リストを読みます）、FTS の結果が薄い場合のフォールバックとして働きます。  
  既存の FTS 索引は起動時に再構築されます。 元の記憶は変更されません。
- 記憶は期間モデルに従います。系統やバージョンはありません。  
  `state` 記憶は期間にわたって保持され（`period_start` / `period_end`、どちらの端も開いている可能性があります）、`event` 記憶は一点で保持されます（`event_at`）。  
  期間のマッチングは重なりによるもので、イベントは、その点が範囲内にある場合にマッチします。

  段階 A は、新しい状態がどの既存行と重なるかを宣言し、バックエンドはそれらの期間を決定論的に調整します（新しい行が勝ちます: トリミング、終了、分割。
  分割された行は独立して存続します）。
  書き込み時の類似度ゲート（内容の類似度が `MEMORY_SIMILARITY_THRESHOLD` 以上）により、保存は重複した挿入ではなく、既存の行への一致になります。
  一致した忘却行は復帰します。

  時刻を確定できない発言は、別プールに provisional（時刻不明）として保存されます。
  段階 A が検索・編集できますが、事実として開示されることは決してありません。
  キャラクターは聞き返し材料としてのみ受け取り、会話の中で時刻を確認し、それにより同じ行が確定します。

- 記憶は時間とともに減衰し（カテゴリごとに1つの半減期。
  既定では出来事 30 日、状態 365 日）、保持スコアがしきい値を下回ると忘れられます。
  非アクティブ化であり、削除は決してされません。
  忘れられた記憶が戻るのは、具体的な手がかりがあった場合だけです（その内容または具体的な語にヒットする検索語）。
  ユーザーがそれを振り返って指し示したとき、それは*想起*されます（その場で再活性化され、想起として数えられ、半減期が長くなります）。
  事実が単に再び述べられたとき、それは*復帰*されます（再活性化され、別に数えられ、想起には決してなりません）。

  抽象的な語だけへのヒットは何も復活させません。
  指し示しがある場合は、段階 B と C への「何か忘れている」という通知（抽象的な語であり、内容は決してありません）になります。
  指し示しがない場合は、段階 A で `forgotten_undisclosed` として止まり、本当のノーヒットとは区別して保持されます。

  復帰された記憶は、復帰したターンでは開示されません。
  次のターン以降、通常のヒットとしてキャラクターに届きます。
  まだ要約されていないメッセージにリンクされた記憶は、最新の記憶とともに、段階 B と C に渡される常駐集合を形成します（ID が衝突した場合は最新の配信が勝ちます）。

  検索から学習された語は、ヒットした側で分類されます（内容または具体的な語に対して証明された語は具体的な語へ昇格し、降格はありません）。
  外れた検索語は、その事実に別の方法で到達したときに抽象的な語として分類されるため、同じ言い回しが次回はそれを見つけられます。

- 現在日時が推測されることは決してありません。
  常に段階 A、B、C に注入され（日付、時刻、曜日、タイムゾーン）、相対的な期間表現（「昨年」）は段階 A がそれを基準に絶対的な期間へ解決します。
- スキーマは起動時に現在のモデル定義から作成され（`create_all`）、その後マイグレーションが走ります。
  スキーマ版数は `schema_version` テーブルで管理され、現在の版数は 1 です。
  刻印のないデータベースは版数 1 として刻印されます。
  新しい版数のデータベースを古いビルドで開くことはできません（起動時に拒否されます）。
- 期限切れの会話ログは、経過時間だけでアーカイブされます（保持によって物理的に削除されることは決してありません。物理削除は purge の経路だけです）。
  その時点までに事実は既に長期記憶の中にあります（段階 A がリアルタイムに書き込むため）。
  アーカイブに要約の前提条件はありません。
  要約は文脈だけに関わるもので、メッセージを隠すことは決してなく、アーカイブの条件でもありません。
  要約は、そのカバー範囲内のすべてのメッセージがアーカイブされた時点で無効化され（アーカイブされ）、その後は文脈に役立ちません。
  物理的な削除は上記の purge 経路だけです。
- API は、Tailscale のような信頼できるネットワーク上に置いてください。公開インターネットへ直接公開しないでください。
- FastAPI の `/openapi.json` が、権威ある機械可読スキーマです。
