# トラブルシューティング

対象読者：セットアップや起動、利用で困っている人。

セットアップと起動、利用でつまずいたときの確認事項です。

## セットアップスクリプトのエラーコード

`setup.bat` がエラーコード（`E001` など）を表示して止まった場合は、次と照らしてください。

| コード | 意味                                                                   |
| ------ | ---------------------------------------------------------------------- |
| `E001` | uv が見つかりません                                                    |
| `E002` | Node.js が見つかりません                                               |
| `E003` | pnpm が見つかりません                                                  |
| `E004` | `uv sync`（バックエンドの依存関係のインストール）に失敗しました        |
| `E005` | `backend/.env` の作成に失敗しました                                    |
| `E006` | `pnpm install`（フロントエンドの依存関係のインストール）に失敗しました |
| `E007` | `frontend/.env` の作成に失敗しました                                   |

## 起動しても画面が出ない

`frontend/dist` が無い状態でプロダクションサーバー(`python prod.py <引数>`で起動する方のサーバー)を起動した場合は、API のみで起動してログに警告が出ます（画面は開けません）。

その場合はフロントエンドをビルドしてから再起動してください。

## チャットで LLM のエラーになる

まず、接続先は `backend/.env` の `LLM_BASE_URL` で指定します（必須で、既定値はありません）。

### ローカル LLM ソフトウェアを接続先にしている

接続先のローカル LLM ソフトウェアは、Remorise とは別に起動しておく必要があります。

起動しているのにエラーが出る場合は、接続先 URL の設定に誤りがないかをよく確認してください。

また、手動設定していない限り通常は設定されていないはずですが、API キーをローカル LLM ソフトウェア側で設定している場合は `backend/.env` の `LLM_API_KEY` にも設定しておく必要があります。

### 外部の LLM プロバイダーを接続先にしている

API キーを `backend/.env` の `LLM_API_KEY` に設定しておく必要があります。

また、接続先 URL の設定に誤りがないかをよく確認してください。

それでも接続できない場合、お使いのコンピューター側の問題かプロバイダー側の問題だと考えられ、Remorise 側ではサポートすることはできません。

## キャラクターの返答がおかしい、賢くない

キャラクターの賢さ、人格、応答の質は、使用している LLM モデルによって大きく変わります。

設定した性格どおりに振る舞わない、会話がかみ合わないといった挙動の多くは、モデルの性能や特性によるものです。

別のモデルに変えると改善する場合があります。モデルに起因する挙動は、Remorise の問題ではありません。

## データベースのバージョン

データベースはスキーマ版数で管理され、起動時に自動でマイグレーションされます。

新しいバージョンで起動したデータベースを古いバージョンの Remorise で開くことはできません（起動時に拒否されます）。

アップデート前に、大切なデータはデータフォルダごとバックアップを取ってください。
