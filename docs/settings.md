# 設定リファレンス

対象読者：Remorise の設定を変更する人。

Remorise の設定は2層に分かれています。
基底層は env ファイルからだけ読み、運用層は env ファイルの値を初期値として、設定画面（データベース）から上書きできます。

## 層と優先順位

- **基底層**：データベースや LLM クライアントを作る前に必要な値（接続先、データの場所）です。
  env ファイルからだけ読みます。
  設定画面には表示のみされ、画面からは変更できません（API キーは値ではなく、設定されているかどうかだけが表示されます）。
- **運用層**：動作の調整値です。
  解決順位は「データベースの上書き > env ファイル > 既定値」で、設定画面で変えると再起動なしで反映されます。
  画面で「DB」と付いた項目はデータベースで上書き中であり、「.env の値に戻す」で上書きを消せます。
  編集項目の入力欄には、プレースホルダとして env ファイル／既定値が表示されます。
- env ファイルは、開発・本番とも `backend/.env` を読みます（本番専用の env ファイルはありません）。

## 基底層（env ファイルのみ）

| 環境変数            | 既定値                                                               | 意味                                                                               |
| ------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `LLM_BASE_URL`      | なし（必須）                                                         | 接続する LLM サーバーの OpenAI 互換 API の URL。未指定だと起動時にエラーになります |
| `LLM_API_KEY`       | なし（必須）                                                         | API キー。ローカル運用では実質使われません。未指定だと起動時にエラーになります     |
| `LLM_MODEL`         | なし（必須）                                                         | リクエストに指定するモデル名。未指定だと起動時にエラーになります                   |
| `REMORISE_DATA_DIR` | ドキュメントフォルダの `Remorise` フォルダ                           | ユーザーデータ（キャラクター、画像、SQLite データベース）の置き場                  |
| `DATABASE_URL`      | なし（選択中のキャラクターのフォルダ内の `remorise(.<profile>).db`） | データベース接続先を直接指定する場合のみ設定します                                 |

## 起動まわりの環境変数

| 環境変数                | 意味                                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REMORISE_DEV_HOST`     | dev.py の待ち受けアドレス。引数 `--host` が優先されます                                                                                                                                                                                                             |
| `REMORISE_PROD_HOST`    | prod.py の待ち受けアドレス。引数 `--host` が優先されます                                                                                                                                                                                                            |
| `REMORISE_PROFILE`      | データベースのプロファイル名（半角英数字、大文字は小文字に統一）。指定するとキャラクターのフォルダ内の `remorise.<プロファイル>.db` を使い、未指定（空欄）なら `remorise.db` を使います。引数 `--profile` が優先されます。`DATABASE_URL` を明示した場合は効きません |
| `REMORISE_CHARACTER_ID` | 動かすキャラクターの ID（データディレクトリの `characters/` 配下のフォルダ名）。未指定なら `remora`（同梱の公式キャラクター）です。引数 `--character` が優先されます。指定した ID が使えない場合は、エラーをログに出して `remora` で起動します                      |

## 運用層（設定画面と env ファイル）

以下は設定画面のグループと項目です。
環境変数名は env ファイルに初期値を書くときの名前で、既定値は env ファイルにも書かれていない場合の値です。
サンプリングの4項目は未設定（画面ではチェックが外れた状態）だとパラメータ自体を送らず、接続先のサーバー側の既定が効きます。

### 生成

| 項目（環境変数）                             | 既定値  | 意味と効き先                                                                                               |
| -------------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------- |
| 生成トークン上限（`LLM_MAX_TOKENS`）         | `2048`  | 返答生成1回あたりの最大トークン数                                                                          |
| LLMのタイムアウト（`LLM_TIMEOUT_SECONDS`）   | `300`   | LLM呼び出し1回のタイムアウト（秒）。生成では最初のトークンまでの待ち時間（プロンプト処理を含む）に効きます |
| Temperature（`LLM_TEMPERATURE`）             | 未設定  | 返答生成のサンプリング。未設定ならサーバー側の既定                                                         |
| Frequency penalty（`LLM_FREQUENCY_PENALTY`） | 未設定  | 同上                                                                                                       |
| Presence penalty（`LLM_PRESENCE_PENALTY`）   | 未設定  | 同上                                                                                                       |
| Repeat penalty（`LLM_REPEAT_PENALTY`）       | 未設定  | 同上                                                                                                       |
| 文脈サイズ（`LLM_CONTEXT_SIZE`）             | `16384` | 文脈組み立てと要約判定の基準になる総トークン数                                                             |

### 文脈と要約

| 項目（環境変数）                                         | 既定値 | 意味と効き先                                                                                               |
| -------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------- |
| 文脈の警告比率（`CONTEXT_WARNING_RATIO`）                | `0.70` | 文脈の使用量が文脈サイズのこの比率に達したときの警告の目安。要約ジョブの投入判定でも余裕の基準に使われます |
| 要約を開始する比率（`CONTEXT_SUMMARY_RATIO`）            | `0.75` | 未要約の文脈がこの比率に達すると、要約ジョブが投入されます                                                 |
| 要約後の目標比率（`CONTEXT_TARGET_RATIO`）               | `0.55` | 要約が文脈の使用量を落とす目標の比率                                                                       |
| 保護する直近メッセージ数（`SUMMARY_PROTECTED_MESSAGES`） | `20`   | 要約の対象から外す直近のメッセージ数                                                                       |

比率の間には「警告比率 ≤ 要約比率」「目標比率 < 要約比率」という制約があり、反すると保存できません。

### ジョブ

| 項目（環境変数）                                | 既定値 | 意味と効き先                                                   |
| ----------------------------------------------- | ------ | -------------------------------------------------------------- |
| ジョブの最大試行回数（`JOB_MAX_ATTEMPTS`）      | `3`    | 失敗した要約ジョブを再試行する上限。起動時の回復でも使われます |
| ジョブの確認間隔（`JOB_POLL_INTERVAL_SECONDS`） | `5`    | バックグラウンドワーカーがジョブを確認する間隔（秒）           |

### 感情

| 項目（環境変数）                                      | 既定値 | 意味と効き先                                                                        |
| ----------------------------------------------------- | ------ | ----------------------------------------------------------------------------------- |
| 感情の半減期（`EMOTION_HALF_LIFE_MINUTES`）           | `30`   | 感情の強さが時間で減衰する半減期（分）。強さが 0.05 を下回ると neutral に収束します |
| 好感度の下限（`AFFINITY_MIN`）                        | `0`    | 好感度の取りうる最小値                                                              |
| 好感度の上限（`AFFINITY_MAX`）                        | `200`  | 好感度の取りうる最大値                                                              |
| 好感度の1回あたりの変化上限（`AFFINITY_DELTA_LIMIT`） | `5`    | 感情分析1回で好感度が動く量の上限（増減とも）                                       |

### 記憶処理

| 項目（環境変数）                                             | 既定値 | 意味と効き先                                                                                                                                                      |
| ------------------------------------------------------------ | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記憶処理の呼び出し上限（`MEMORY_AGENT_MAX_CALLS`）           | `8`    | 記憶処理（段階 A）のツールコール回数の上限（1ターン）。ほかに時間とトークンの総量予算があり、最初に達したもので打ち切って、その時点までの確定分でターンを進めます |
| 記憶処理のタイムアウト（`MEMORY_AGENT_TIMEOUT_SECONDS`）     | `60`   | 記憶処理セッションの時間上限（秒）                                                                                                                                |
| 受け渡す記憶の件数上限（`MEMORY_HANDOVER_LIMIT`）            | `5`    | 1回の検索から感情分析と返答生成へ受け渡す記憶の件数上限。検索そのものの範囲は変わりません                                                                         |
| 受け渡す記憶のトークン予算（`MEMORY_HANDOVER_TOKEN_BUDGET`） | `1500` | 受け渡す記憶と常駐集合で共有するトークン量の上限                                                                                                                  |
| 常駐集合の件数上限（`MEMORY_RESIDENT_MAX_ITEMS`）            | `20`   | 未要約のメッセージに紐づく記憶（常駐集合）の最大件数。最近紐づいたものから残ります                                                                                |
| 内容類似の照合しきい値（`MEMORY_SIMILARITY_THRESHOLD`）      | `0.8`  | 新しい記憶の内容が既存の行とこの値以上に似ていれば、新規登録せず既存の行への一致として処理します（忘却中の行なら復帰します）                                      |

### 記憶の忘却

保持スコアは「（重要度 / 5）× 0.5^(経過日数 / 半減期)」で計算し、最後に強化されてから経過した時間で減衰します。

| 項目（環境変数）                                           | 既定値 | 意味と効き先                                                             |
| ---------------------------------------------------------- | ------ | ------------------------------------------------------------------------ |
| 忘却を有効にする（`MEMORY_DECAY_ENABLED`）                 | `true` | 保持スコアによる忘却処理のオン・オフ                                     |
| 忘却する保持スコアのしきい値（`MEMORY_DECAY_THRESHOLD`）   | `0.2`  | 保持スコアがこの値を下回った記憶が忘却されます（削除ではなく無効化です） |
| 半減期（出来事）（`MEMORY_HALF_LIFE_EVENT_DAYS`）          | `30`   | 出来事の記憶の保持スコアの半減期（日）                                   |
| 半減期（状態）（`MEMORY_HALF_LIFE_STATE_DAYS`）            | `365`  | 状態の記憶の保持スコアの半減期（日）                                     |
| 想起ごとの半減期の倍率（`MEMORY_REACTIVATION_FACTOR`）     | `1.5`  | 忘れた記憶が想起されるたびに、実効半減期へ掛ける倍率                     |
| 半減期の倍率の上限（`MEMORY_REACTIVATION_MAX_MULTIPLIER`） | `10`   | 想起による倍率の累積上限                                                 |

### ライフサイクル

| 項目（環境変数）                                               | 既定値 | 意味と効き先                                                                                                                                                                                    |
| -------------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| アーカイブの自動物理削除までの日数（`ARCHIVE_RETENTION_DAYS`） | `0`    | アーカイブ済みの会話履歴を自動で物理削除するまでの日数。0 のときは自動削除せず、手動の purge だけが物理削除します                                                                               |
| LLM 生ログの保持日数（`RAW_LOG_RETENTION_DAYS`）               | `30`   | LLM のリクエストと生応答のログを保持する日数。ジョブに属する行は、そのジョブが完了するまでは保持されます。`v0.1.0` 時点では DB ファイルを直接開いて確認するしか生ログを確認する方法はありません |

### 立ち絵モーション

立ち絵は表示レイヤーをシートに合成し、グリッドメッシュの変形（呼吸と上半身の横ずれ）で動かします。
原則は1枚のシートで、レイヤー単体がずれる動きはありません。
ただし `depth: "rear"` のレイヤー（後ろ髪など）だけは別のシートに合成され、シート同士が最大で数 px ずれる視差があります。
このグループは立ち絵デバッグ画面（`/sprites`）からもプレビューしながら変更できます。

| 項目（環境変数）                                  | 既定値 | 意味と効き先                                                       |
| ------------------------------------------------- | ------ | ------------------------------------------------------------------ |
| モーションを有効にする（`SPRITE_MOTION_ENABLED`） | `true` | 立ち絵モーションのオン・オフ                                       |
| 動きの大きさ（`SPRITE_MOTION_AMPLITUDE`）         | `1.0`  | 呼吸・上半身の横ずれの大きさの倍率（0〜2、1 がレンダラーの標準量） |
| 速さ（`SPRITE_MOTION_SPEED`）                     | `1.0`  | モーションの速さの倍率（0より大きく3まで）                         |
| オーバースキャン（`SPRITE_MOTION_OVERSCAN`）      | `1.06` | 動きの端を画面内に収めるための固定ズーム（1〜1.5）                 |

## 表示設定（ブラウザ側）

設定画面の上部にある項目は、このブラウザに保存される表示設定です（バックエンドには送られません）。

| 項目                               | 既定値   | 意味と効き先                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| デバッグモード                     | オフ     | 記憶の閲覧、会話履歴の物理削除、立ち絵の確認、トークンの内訳などのデバッグ表示を有効にします                                                                                                                                                                                                                                                                                                                              |
| デバッグ情報をデフォルトで展開する | オフ     | デバッグモードのときにだけ出る設定です。前段処理、パイプライン、要約などの情報ブロックを最初から開いた状態で表示します（トークン消費は常に対象外で、常に表示されます）                                                                                                                                                                                                                                                    |
| 配色                               | デバイス | ライト／ダークの切り替え。デバイスは端末の設定に追従します                                                                                                                                                                                                                                                                                                                                                                |
| キャラクターのテーマ色相を使う     | オン     | 有効にすると、色相はキャラクター設定のテーマ色相（`theme_hue`）に追随し、下の色相は効かなくなります。テーマ色相を持たないキャラクターでは、既定の色相（314）になります。テーマ色相の値自体はブラウザに保存されません                                                                                                                                                                                                      |
| 色相                               | —        | UI の色相（0〜360）                                                                                                                                                                                                                                                                                                                                                                                                       |
| グラデーションの長さ               | 20%      | 立ち絵とメッセージの境目をぼかす長さ。メッセージ領域の高さに対する割合（0〜100%）で決まり、被さり量を超えることはありません。立ち絵の足元のぼかしは固定で、この設定では変わりません                                                                                                                                                                                                                                       |
| 立ち絵への被さり具合               | 40%      | チャット画面のヘッダーにある高さ調整ボタンから、立ち絵とメッセージの境界をドラッグして決める、メッセージが立ち絵に被さる量（立ち絵の高さに対する割合、15〜85%の範囲に制限）。立ち絵の表示サイズ自体は変わりません                                                                                                                                                                                                         |
| 立ち絵デバッグでの被さり具合       | 40%      | 立ち絵デバッグ画面（`/sprites`）専用の被さり具合。モバイルでは操作項目の列が立ち絵に被さり、画面のヘッダーにある高さ調整ボタンから境界をドラッグして決めます（立ち絵の高さに対する割合、15〜85%の範囲に制限）。チャット画面の被さり具合とは別に保存され、互いに影響しません。同じ画面のヘッダーにある表示設定からは、グラデーションの長さと背景の不透明度も専用に設定できます（未設定の間はチャット画面の値に追従します） |
| メッセージ背景の不透明度           | 75%      | 立ち絵に被さるメッセージ領域の背景の濃さ（50〜100%）。境目のグラデーションは、「グラデーションの長さ」の範囲で透明からこの不透明度まで遷移します。下げるほど立ち絵が透けて見え、立ち絵の下端は切れ目が目立たないよう常にうっすらフェードします。文字の読みやすさを保つため50%未満にはできません                                                                                                                           |
| 文字・項目の不透明度               | 100%     | メッセージの文字や項目そのものの濃さ（50〜100%）。チャット画面と立ち絵デバッグ画面の両方に効きます。下限はメッセージ背景の不透明度と同じ50%です                                                                                                                                                                                                                                                                           |
