# キャラクター設定フォーマット

対象読者：キャラクターを自作する人。

キャラクターは「プロフィール（`character.json`）」と「立ち絵（`layers.json` ＋画像）」で構成されます。
この文書は両ファイルの形式仕様です。
`character.json` の記入例は、リポジトリ同梱の公式キャラクター「レモラ」（`characters/remora/character.json`）の実際の値です。

## 配置

```text
<REMORISE_DATA_DIR>/
  characters/
    <id>/
      character.json   # プロフィール（必須）
      layers.json      # 立ち絵の定義（任意。無ければ立ち絵なし）
      terms.md         # キャラクター利用規約（任意。無ければ規約なし）
      layers/          # レイヤー画像（layers.json から相対パスで参照）
      remorise(.<profile>).db      # このキャラクターのデータベース（自動で作られます）
```

- キャラクターの置き場は2か所あります。
  ユーザーデータ側の `REMORISE_DATA_DIR/characters/<id>/`（上の図）と、リポジトリ同梱の `characters/<id>/` です。
  同梱側の構成も同じですが、データベースは同梱側には作られません。
  フォルダ名がそのままキャラクター ID で、動かすキャラクターは起動引数 `--character` か環境変数 `REMORISE_CHARACTER_ID` で選びます。
  指定がなければ `remora` です。
- 起動時の解決はフォルダ単位です。
  まずデータ側の `characters/<id>/character.json` を読み、読めたらそのフォルダが解決先になります。
  読めない場合、ID が `remora` 以外ならエラーをログに出して `remora` で同じ判定をし、`remora` でもデータ側が読めなければ同梱の `characters/remora/` が解決先になります。
  同梱の `remora` すら読めない場合は起動時にエラーになります。
- 解決先が決まれば、`character.json`、`layers.json`、`terms.md`、画像はすべてそのフォルダからだけ読みます。
  ファイル単位のフォールバックはありません。
  たとえば解決先のフォルダに `layers.json` が無ければ、同梱側に定義があっても使われず、立ち絵なしになります。
- データベースは常にデータ側です。
  解決先が同梱フォルダの場合でも、そのキャラクターのデータベースはデータ側の `characters/<id>/` の中に作られます。
  サーバーは1プロセスにつき1キャラクターで動き、データベースもキャラクターごとに分かれます。
- 画像ディレクトリは解決先フォルダ内の `layers/` です。
- 立ち絵データが実在しないキャラクター（`layers.json` が無い、または参照画像が1枚も存在しない）は「立ち絵なし」として扱われます。
  バックエンドが `GET /api/character/layers` の応答に `available` を含めて判定を伝え、フロントはチャット画面に立ち絵エリアを出さず、立ち絵デバッグ（`/sprites`）も使えません。
  一部の画像だけが欠けている場合は、存在するものだけで描画します（代替画像での補完はしません）。

## character.json

| 項目               | 型       | 必須 | 説明                                                                                                                                                                               |
| ------------------ | -------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`             | string   | ○    | 表示名                                                                                                                                                                             |
| `profile`          | string   |      | 短い紹介文                                                                                                                                                                         |
| `personality`      | string[] |      | 性格の箇条書き                                                                                                                                                                     |
| `speech_style`     | string   |      | 口調の指定。空ならシステムプロンプトに何も追加しない                                                                                                                               |
| `sentence_endings` | string   |      | 語尾の例。`speech_style` とは別の項目としてシステムプロンプトに渡す。空なら何も追加しない                                                                                          |
| `first_person`     | string   |      | 一人称（既定「私」）                                                                                                                                                               |
| `second_person`    | string   |      | 二人称（既定「あなた」）                                                                                                                                                           |
| `relationship`     | string   |      | 相手との関係                                                                                                                                                                       |
| `background`       | string   |      | 背景設定                                                                                                                                                                           |
| `gender`           | string   |      | 性別。空ならシステムプロンプトに何も追加しない                                                                                                                                     |
| `birthday`         | string   |      | 誕生日。空なら何も追加しない                                                                                                                                                       |
| `appearance`       | string   |      | 容姿。空なら何も追加しない                                                                                                                                                         |
| `theme_hue`        | number   |      | UI のテーマ色相（0〜360）。クライアントの表示設定で「キャラクターのテーマ色相を使う」が有効なとき、UI の色相がこの値に追随する（未設定の場合は既定の 314）。プロンプトには渡らない |
| `initial_state`    | object   |      | 初期状態：`emotion`（感情キー）、`intensity`（0〜1）、`mood`、`affinity`（0〜200）。DBに状態が無いときだけ使われる                                                                 |
| `extra_settings`   | object   |      | 予備の自由設定                                                                                                                                                                     |

`name` 以外はすべて任意です。
自由記述の項目は、空でなければ項目ごとの行（「口調：」「性別：」など）としてシステムプロンプトに渡り、空ならその行自体が出ません。

表にない項目は無視されます。
`initial_state` や `theme_hue` の数値が範囲外だったり、`emotion` が感情キーでなかったりすると、`character.json` 全体が読み込めなかったものとして扱われ、配置の規則どおりフォールバックします。

### 書き方の目安

項目ごとに、どういう形で書けばいいかと短い記入例を示します。

- `name`：単語（名前そのもの）。画面の表示名になり、プロンプトにもそのまま出ます。
  例：`"レモラ"`
- `profile`：自由文。1〜2文の短い紹介を書きます。
  例：`"みんなに人気のケモミミの生えた魚娘。"`
- `personality`：文字列のリスト。1要素に性格の一面を短く書き、複数並べます。文にする必要はありません。
  例：`["元気ハツラツ", "好奇心旺盛", "おっちょこちょい"]`
- `speech_style`：自由文。
  口調の方針（丁寧さ、文の長さ、話の進め方など）を文で書きます。
  語尾の実例はここには書かず、`sentence_endings` に分けます。
  例：`"元気で勢いがある。伸ばし棒（ー）を多用する。ついついいらないことまで口走ってしまう。"`
- `sentence_endings`：語尾の実例を並べる項目です。
  方針を書く場所ではなく、「文をどう締めるか」の見本を、句点区切りで短く複数並べます。
  文そのもの（主語や述語のある文章）は書きません。
  例：`"～だよねー。～だよー。～じゃない？"`
- `first_person` / `second_person`：単語。一人称・二人称そのものを書きます。
  例：`"あたし"` / `"あんた"`
- `relationship`：短い自由文。相手との関係を名詞句や短い文で書きます。
  例：`"ユーザーのことが気になっているらしい。"`
- `background`：自由文。経歴、立場、暮らしなどを文で書きます。
  例：`"いつも海辺で遊んでいる。魚娘なくせに泳ぐのは苦手だとか。"`
- `gender`：単語で書きます。値は「性別：」の行にそのまま入るので、説明文にはしません。
  例：`"女性"`
- `birthday`：日付として書きます。
  年まで書いても、月日だけでも構いません。
  機械的に決まった形式は要求されませんが、日付だと分かる書き方にしてください。
  年齢を書く項目ではありません。
  例：`"8月30日"`
- `appearance`：自由文。
  見た目を1つの文字列として文で書きます。
  項目分けの仕組みはないので、髪、目、服装などを読点でつないで書くか、短い文を重ねて書きます。
  例：`"ケモミミが生えている。金色を基調に、紫色とピンクがアクセントに入った髪。水色とピンクのグラデーションのかかったエラが顔の左右にある。青色のキラキラした目。紫色のリボンが胸についたマリンセーラー服を着ている。水色の尾びれが生えている。"`
- `theme_hue`：0〜360 の数値。
  そのキャラクターのテーマカラーの色相を書きます。
  例：`314`
- `initial_state`：オブジェクト。
  `emotion` は感情キー、`mood` は気分を表す自由な文字列、`intensity` は 0〜1 の数値、`affinity` は 0〜200 の数値です。
  `emotion` に使える感情キーは `neutral`、`happy`、`sad`、`angry`、`embarrassed`、`surprised`、`anxious`、`affectionate`、`puzzled` の9つです。
  データベースに状態が保存されていない最初の会話だけに使われます。
  例：`{ "emotion": "neutral", "intensity": 0.0, "mood": "neutral", "affinity": 50 }`
- `extra_settings`：キーと値のオブジェクトです。
  キーが項目名、値がその内容になり、まとめて「追加設定：」としてシステムプロンプトに渡ります。
  決まった項目名はなく、キャラクターごとに自由に増やせます。
  値の書き方は内容次第で、単語でも文でも構いません。
  例：`{ "好きな食べ物": "焼き魚、スイカ", "苦手なこと": "泳ぐこと" }`

## layers.json

立ち絵は「フルキャンバスのレイヤー画像を決まった順に重ねる」構造です。

| 項目                         | 説明                                                                                                                                                                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `image`                      | `{ "width": 1024, "height": 1536 }` のようなキャンバスサイズ。全レイヤー画像はこのサイズ（または後述のパーツ形式）で揃える                                                                                                                                     |
| `paint`                      | 描画順（スロット名の配列）。通常は `["pose", "expression", "mouth", "eyes", "tears", "extras", "mark"]`                                                                                                                                                        |
| `poses`                      | ポーズ名 → レイヤー参照の配列、または `{ "label": "表示名", "layers": [参照...] }`。配列（または `layers`）は下（奥）から順に重ねる。`label` は立ち絵デバッグの表示名で、無いときはポーズ名をそのまま出す。ポーズの追加はこの定義だけで足りる                  |
| `expressions`                | 表情名 → `{ "base": 参照 or 参照の配列 or null, "mouth": [参照 or 参照の配列 or null × 3] }`。任意で表情ごとの目追加レイヤー（`eyes` / `eyes_left` / `eyes_right`）も持てる                                                                                    |
| `eyes`                       | 瞬きフレームの配列（添字 0=開、1=半閉じ、2=閉じ）。各フレームはレイヤー参照の配列                                                                                                                                                                              |
| `eyes_left` / `eyes_right`   | 左右別の瞬きフレーム（任意）。どちらかがあると左右別モードになり、各側は自分のフレームで描かれる。共通の `eyes` は読まない                                                                                                                                     |
| `tears`                      | 涙レイヤー。`eyes` と同じ添字でフレームが対応する                                                                                                                                                                                                              |
| `tears_left` / `tears_right` | 左右別の涙レイヤー（任意）。`tears` と同じ添字で、各側の目のフレームに別々に追従する。共通の `tears` は読まない                                                                                                                                                |
| `extras`                     | 装飾レイヤーの名前 → 参照（または参照の配列）。汗や頬の赤みなど、感情ごとに切り替える装飾を名前で定義する                                                                                                                                                      |
| `marks`                      | マーク名 → 参照（または参照の配列）。感情マークや「考え中」マークなど                                                                                                                                                                                          |
| `blink`                      | 瞬きのタイミング：`cycle`（フレーム列）、`stepMs`、`perMinute`、`hurriedPerMinute`（慌ただしい表情用）、`minGapMs`、`hurriedExpressions`                                                                                                                       |
| `talk`                       | 口パクのタイミング：`cycle`（口フレーム列）、`intervalMs`                                                                                                                                                                                                      |
| `frame_mode`                 | フレームの重ね方（任意）。`{ "eyes": ..., "tears": ..., "mouth": ... }` の形で、目・涙・口それぞれに `"switch"`（選んだフレームだけを描く個別切り替え）か `"stack"`（選んだフレームまでの全フレームを重ねる段階重ね）を指定する。書かなかった項目は `"switch"` |
| `emotions`                   | 感情キー → `{ "pose", "expression", "mark", "extras", "tears" }` の見た目対応表。`extras` は有効にする装飾名の配列。`neutral` がフォールバック                                                                                                                 |
| `parts`                      | パーツ形式で変換済みのときに `true`（変換ツールが付ける。描画側は無くても判別できる）                                                                                                                                                                          |
| `available`                  | ファイルには書かない。バックエンドが応答に付ける立ち絵有無の判定                                                                                                                                                                                               |

### レイヤー参照の2形式

- **通常形式**：パス文字列（例 `"face/base.png"`）。
  `layers/` からの相対パスで、キャンバス全体サイズの画像を原点 (0, 0) に描く。
- **パーツ形式**：`{ "path": "face/base.png", "x": 290, "y": 180 }` のようなオフセット付きオブジェクト。
  不透明部分だけに切り詰めた小さい画像を、左上が (x, y) になるよう描く。

両形式は混在でき、描画側はどちらも読めます。
通常形式のキャラクターをパーツ形式へ変換するツールが `backend/tools/split_sprite_layers.py` です：

```bash
cd backend
uv run python tools/split_sprite_layers.py <character dir> [--out <dir>]
```

変換は**透過トリムのみ**です（不透明部分のバウンディングボックスで切り出し、オフセットを付ける）。

表情ベースのような1枚絵を画像間差分で分割することはしません（ベースは閉じた口を含んだ1枚絵で、分割すると切れ目の恐れがあるため）。

口パクの開口レイヤーはもともと口元だけの小さいパッチで、ベースの顔に描かれた閉じた口の上に重ねる構造であり、トリムだけで十分に小さくなります。

変換は元データを変更せず、変換前後で全スタックの再合成がピクセル単位で一致することを自動検証してから出力します（一致しない場合は失敗します）。

### 奥行き区分（`depth`）

オブジェクト形式の参照には、奥行き区分 `depth` を付けられます。

キャラクター自身の後ろ側のパーツ（後ろ髪、スカートの後ろ側など）を `"rear"` にすると、そのレイヤーは背面シートとして前面とは別に合成され、少し拡大されたうえで、変位を弱めたワープで前面の後ろに描かれます。

呼吸や上半身の横ずれに対して背面がわずかに遅れて動くため、視差として奥行きが出ます。
場面の背景を指定するものではありません。

```json
{ "path": "hair/back.png", "depth": "rear" }
```

- 値は `"rear"`（背面）か `"front"`（前面）。省略時は `"front"` で、文字列形式の参照は常に前面です。
- オブジェクト形式では `x` と `y` も省略でき、その場合は 0 として扱います（フルキャンバス画像に `depth` だけを付けたいときはこの形を使います）。
- パーツ形式と併用できます（`{ "path": ..., "x": ..., "y": ..., "depth": "rear" }`）。
  分割ツールで変換しても `depth` は保持されます。
- 視差はモーションの一部です。モーション無効時は従来どおり全レイヤーを1枚に合成して描くため、作画どおりの位置で重なります。

### 表情と口パク

- `expressions.<name>.base` が顔の基本絵（閉じた口を含む）で、`null` の場合は顔ベースなし（口パクや目だけで表現する表情）。
- `mouth` は添字 0=閉、1=半開、2=開 の3段階で、発話中は `talk.cycle` の順に切り替わります。使わない段階は `null`。
- 目は `eyes` のフレーム列を瞬きアニメーションが切り替えます。涙は目のフレームに同期します。
- 左右別のフレーム（`eyes_left` / `eyes_right`）がある場合は、各側が自分のフレーム列で切り替わります。
  瞬きは左右共通で、両目とも開いているときだけ走ります。
  左右別に開閉状態を選べるのは立ち絵デバッグ画面だけで、チャット画面では両目共通の状態を使います。
  涙も左右別（`tears_left` / `tears_right`）にでき、各側の目のフレームに別々に追従します。
- フレームの重ね方は `frame_mode` で目・涙・口それぞれに選びます。  
  `"switch"`（既定）は各フレームが完結した1枚絵で、選んだフレームだけを描きます。  
  `"stack"` は選んだフレームまでの全フレームを下から重ねるので、半閉じ・閉じや半開きの口は、開いた状態の上に重ねる差分として描く作りになります。  
  左右別と共通は混ぜて読まず、左右別がある場合はそちらだけ、無い場合は共通だけを読みます。目と涙は、左右別と共通のどちらも無い場合はエラーになります。
- `base`、`mouth` の各フレーム、`marks` の値は、参照1つではなく参照の配列でも書けます。
  配列は書いた順に重ねて描きます（顔を複数枚で合成する、口のパッチを重ねる、など）。
- 表情ごとに目追加レイヤーを持てます。
  `expressions.<name>` に `eyes` / `eyes_left` / `eyes_right`（目のフレームと同じ添字の配列）を書くと、その表情のときだけ、共通の目レイヤーの上にそのフレームの分が追加で描かれます。  
  追加レイヤーは `frame_mode` の `"stack"` には従わず、そのフレームに書いた分だけを描くので、目の状態によらず常に出すもの（頬のオーバーレイなど）は全フレームに書きます。  
  左右別の読み分けも共通の目リストと同じで、左右別がある場合はそちらだけを読みます（追加自体が無い場合は何も描きません）。
- 装飾レイヤーは `extras` に名前で定義し、感情の見た目対応表（`emotions`）の `extras` に名前を並べた感情でだけ描きます。  
  汗や頬の赤みのほか、名前を増やせば装飾を足せます。
- チャットでキャラクターが考え中の間は、`thinking` という名前のマークが、感情のマークの上に重ねて描かれます（感情にマークが無いときは `thinking` だけが出ます）。

### モーション

立ち絵のモーションは、表示レイヤーを1枚に合成してから、その合成画像をグリッドメッシュ（20×28、WebGL描画）で変形させて付けます。

レイヤーが個別にずれる動きはなく、レイヤー単位で起きるのは差し替え（瞬き・口パク・表情）だけです。

ただし奥行き区分 `depth` が `"rear"` のレイヤーがある場合は、その背面シートがもう1枚の合成として前面シートの後ろに描かれ、同じ変位場を弱めたゲインで動くため、シート同士の間にだけ視差が生じます（レイヤー単位のずれではありません）。

変形の中身は2つだけです：呼吸（足元を固定し、上へ行くほど変位が大きくなる縦方向の持ち上がりで、上半身が呼吸周期でゆっくり上下する）と、上半身の横ずれ（頭部から上半身にかけてのごく小さな横方向のずれで、下半身には及ばない）。

大きさの脈動（前後に動いて見える動き）や身体全体の傾きは付けません。

合成全体への変換（オーバースキャンのズームと、発話開始時の小さな跳ね）も併用し、動きで端がフレームから離れないよう少し拡大して描きます。

パラメータはサーバー設定の運用層（DB保存、再起動なしで反映）です：

| 設定キー                  | 既定 | 範囲             | 意味                         |
| ------------------------- | ---- | ---------------- | ---------------------------- |
| `sprite_motion_enabled`   | true |                  | モーションの有効/無効        |
| `sprite_motion_amplitude` | 1.0  | 0〜2             | 呼吸・上半身の横ずれの大きさ |
| `sprite_motion_speed`     | 1.0  | 0より大きく3まで | 速さ                         |
| `sprite_motion_overscan`  | 1.06 | 1〜1.5           | 端の離れ防止の拡大率         |

通常の設定画面と立ち絵デバッグ（`/sprites`）の両方から変更でき、デバッグ側ではプレビューへ即時反映されます。

## 利用規約（terms.md）

キャラクターのフォルダに `terms.md` を置くと、そのキャラクターの利用規約として扱われます。Markdown で書きます。

- 規約はキャラクターの作者の文書です。
  Remorise は内容に関与せず、About（「Remorise について」）から開ける「キャラクター利用規約」のページにそのまま表示するだけです。
- `terms.md` が無いキャラクターには利用規約はなく、About にも開くボタンは出ません。
- キャラクターを配布するときは、フォルダごと渡すことで規約も一緒に付いていきます。
- 公式キャラクター「レモラ」の規約は、同梱フォルダの `characters/remora/terms.md` にあります。
